# M876 — priority dialog response

`M876 S<n>` selects button `n` from the currently active firmware dialog,
using a zero-based index in the same order the buttons are shown and reported
to remote clients.

The command is handled directly by the serial receiver. While an actionable
pause or error is active, the receiver opens two reserved command slots beyond
the normal streaming queue: one for a line the host had already transmitted
and one for the service action. This keeps `M876`, abort commands, and direct
stuck-filament responses usable when the normal G-code queue is full.

Examples:

```gcode
M876 S0 ; select the first displayed action (Retry on an MMU error)
M876 S1 ; select the second displayed action
```

The requested index is validated against the current top-most dialog. An
invalid index or a command sent without a matching active dialog is
acknowledged and ignored, so it cannot affect a later prompt.

Dedicated recovery commands remain available:

```gcode
M1601 C ; continue after inspecting a stuck-filament warning
M1601 U ; unload after a stuck-filament warning
M1601 A ; abort after a stuck-filament warning
M604    ; abort a serial print
M524    ; abort the active print
```
