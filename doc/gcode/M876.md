# M876 — priority service status and dialog response

`M876 S<n>` selects button `n` from the currently active firmware dialog,
using a zero-based index in the same order the buttons are shown and reported
to remote clients.

`M876 A"<name>"` selects the same action by its stable canonical name. Names
are matched case-insensitively, so they do not depend on translated UI text or
button order:

```gcode
M876 A"Retry"
M876 A"Unload"
M876 A"Continue"
M876 A"Abort"
```

The command is handled directly by the serial receiver. Two hidden reserved
command slots beyond the normal streaming queue remain active at all times:
one for a line the host had already transmitted and one for the service
action. This keeps `M876`, pause, abort, and direct stuck-filament responses
usable when the normal G-code queue is full or a heater wait is blocking.

Examples:

```gcode
M876 S0 ; select the first displayed action (Retry on an MMU error)
M876 S1 ; select the second displayed action
```

The requested index is validated against the current top-most dialog. An
invalid index or a command sent without a matching active dialog is
acknowledged and ignored, so it cannot affect a later prompt.

## Query service state

`M876 Q` reports the normal and hidden queue usage, numeric Marlin print state,
stable-pause state, whether generic resume is currently safe, the blocking
serial command, and the canonical actions offered by the top-most dialog:

```text
SERVICE_QUEUE normal=8/8 reserve=1/2 state=11 paused=1 resume=0 blocking=M109 actions=Retry,Abort
```

Hosts should enable a generic Resume action only when `resume=1`. A recovery
dialog must instead be answered with one of the reported action names or its
button index.

Dedicated recovery commands remain available:

```gcode
M601   ; cancel an active heater wait and pause immediately
M602   ; resume only from a stable pause with no blocking recovery dialog
M1601 C ; continue after inspecting a stuck-filament warning
M1601 U ; unload after a stuck-filament warning
M1601 A ; abort after a stuck-filament warning
M604    ; abort a serial print
M524    ; abort the active print
```

Only the documented safety and recovery commands receive immediate priority
handling. Ordinary print, motion, extrusion, and heater commands retain normal
queue ordering even if they were already in flight when the advertised queue
became full.

## Capability discovery

`M115` reports the following when this protocol is available:

```text
Cap:PRIORITY_COMMAND_QUEUE:1
Cap:DIALOG_RESPONSE:1
Cap:NAMED_DIALOG_RESPONSE:1
Cap:SERVICE_QUEUE_STATUS:1
```
