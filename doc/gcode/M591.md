# M591 filament monitoring policy

`M591` controls the persistent filament-monitoring policy on loadcell
printers:

```gcode
M591 S1 P ; enable and persist presence/runout detection
M591 U1 P ; enable and persist movement-collapse detection
M591 S0 U0 P ; disable both optional detectors
M591 R ; restore the persisted policy after a temporary change
M591 ; report the live policy
```

`P` makes an `S` or `U` change persistent. Without `P`, it applies until a
restore or reboot. `I` and `F` retain their legacy E-stall skip/forget tuning
semantics on non-INDX loadcell machines.

## INDX behavior

- `S` controls **Loadcell Filament Runout**. The detector watches actual
  executed forward E motion and requires meaningful calibrated flow. It first
  qualifies 0.75 seconds and 0.75 mm of continuous extrusion, then requires
  more than another 1 second and 1 mm with no pressure evidence. Tiny seam
  moves, retraction, travel, or healthy pressure cannot satisfy that sequence.
- `U` controls **Loadcell Filament Movement**. It reports filament not moving
  only after nozzle pressure was established and then remained collapsed for
  the conservative long qualification/confirmation window.
- Calibrated flow-pressure breakout/max-flow detection is unchanged and always
  enabled. `S0 U0` does not disable this safety path.

The loadcell infers filament behavior from nozzle pressure; it is not a direct
optical or rotary filament encoder. A valid runtime pressure reference from
the INDX PA calibration is required before either optional detector can act.

Automatic outcomes report matching RME errors and open distinct recovery
screens:

| Condition | Internal command | RME workflow/code |
|---|---|---|
| No pressure from start | `M1601 R1` | `filament_runout` / `runout` |
| Established pressure collapsed | `M1601 R2` | `filament_movement` / `not_moving` |
| Flow-pressure breakout | `M1601 R3` | `extrusion_flow_limit` / `flow_limit` |

All use the same safe Continue/Unload/Abort recovery mechanics; only the cause,
guidance, and host diagnostic differ.

For an RME session subscribed to error events, each row produces:

```text
RME_EVENT seq=<n> type=error workflow=<workflow> state=waiting code=<code> message="<message>"
```

Plugins should preserve the condition until the associated recovery FSM closes
or the print is aborted. A later generic filament-change progress event is not
evidence that the original cause changed.
