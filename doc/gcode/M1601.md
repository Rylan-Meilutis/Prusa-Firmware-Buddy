# M1601 extrusion-fault recovery

`M1601` enters the common extrusion recovery flow. Its optional `R` value
selects the physical cause shown on the printer and reported to an RME host:

```gcode
M1601 R0 ; legacy extruder-stall / stuck-filament fault (also the default)
M1601 R1 ; INDX loadcell runout: extrusion began without pressure
M1601 R2 ; INDX filament-not-moving: established pressure collapsed
M1601 R3 ; calibrated flow-pressure breakout / max-flow limit
```

All four screens offer **Continue**, **Unload**, and **Abort**, but their title
and guidance describe the actual fault rather than labeling every condition as
stuck filament.

A connected serial host can select the same actions:

```gcode
M1601 C ; treat as a false detection and continue the print
M1601 U ; unload filament and remain in the filament-change workflow
M1601 A ; abort the print
```

Exactly one action letter is required. Response commands are accepted directly
from serial receive while the recovery command owns the foreground G-code
slot, so OctoPrint can send them while it considers the printer paused. A
response sent without an active extrusion-fault prompt is acknowledged and
ignored; it cannot start or alter a later recovery.

For subscribed RME sessions, automatic faults are emitted before the recovery
command as `RME_ERROR` events with stable workflow/code pairs:

- `workflow=filament_runout code=runout`
- `workflow=filament_movement code=not_moving`
- `workflow=extrusion_flow_limit code=flow_limit`

The workflow names, codes, and messages are stable protocol fields. Hosts
should route by workflow first and code second; they must not parse translated
screen text. The subsequent load/unload FSM is the common actionable recovery
mechanism and does not replace the cause-specific error event.

Continue finishes the pause without unloading, restores the saved X/Y/Z print
position through the normal `M600` recovery path, clears and rearms the
pressure fault monitor, and then resumes. Unload enters the normal material
unload/change flow. Abort uses the normal print-abort cleanup.
